## 6. 스튜디오에 되돌려 줄 것 (아직 전달 안 됨)

이 저장소에서 확인한 사실이다. **스튜디오 문서는 스튜디오가 고친다** — 여기는 「무엇을 알려야 하는가」만 적는다.

| | 내용 |
|---|---|
| **A ⚠** | `PROGRESS.md` §2 가 배경 규격을 **1024×1418** 로 적고 근거를 `STUDIO_VERDICT` §0-B 로 달았다. 그 판정의 결론은 **「1024×1536 그대로 두라」**다. 그 표만 보고 발주하면 못 쓸 규격이 나온다 |
| **B ⚠** | `brief/ART_DIRECTION.md` §4-1 의 그림↔밴드 **대조표 두 줄이 계산 방향이 뒤집혀 있다** (그림 60 → 57.1 · 73 → 71.1 로 적혀 있다). 같은 절의 **환산식 자체는 맞고**, 식대로 풀면 **60 → 60.8 · 73 → 74.9 · 95 → 98.7** 이다. 게임 쪽 실측(`LocationView._background_src()`)도 같은 값이다. §4-1 의 「게임 값 70.0~95.0 → 그림 71.9~95.1」 예시도 같은 이유로 뒤집혀 있다 — 바른 값은 **그림 68.5~91.6%** |
| | **→ 결론은 바뀌지 않는다.** 두 장면의 walkbox 는 여전히 규정 안이고 실제로 그려진 바닥 위에 있다. 틀린 것은 표뿐이다 |
| **C** | `floor_band` 인계 규격 받았다. 주문서 6장에 **「맨 아래 5%에 걸을 자리를 두지 마라」**를 넣었고, 후보 2장의 실측값(황소항 65~100% · 지하철 58~100%)을 게임 문서에 기록했다 |
| **D** | 초상 P1 전달 규격 확인 — **189×189 · 투명 배경 · 파일명은 `character_id`** (`han_gaemi` · `broker` · `sera` · `boss` · `park`). 이 이름으로 오면 코드 수정 없이 붙는다 |
| **E** | 후보 PNG 2장을 게임 저장소에서 **뺐다**. 세 곳에 같은 파일이 있었다 — 후보 정본은 스튜디오 `candidates/backgrounds/` 다 |
| **F** | 배경 주문서 6장을 스튜디오 `brief/` 로 옮길 것인지 (전략 §4). 옮기지 않는다면 **게임 저장소가 정본**이라고 서로 적어 두는 편이 낫다 |
| **G** | 인물 크기 — 게임은 D3 결정까지 32×48 을 유지한다. 지금 있는 유일한 실측 근거는 **목업 인물 = 월드 밴드의 30%(약 395px)** 이고, 배경 그림에 사람이 그려져 있으므로 후보 배경이 더 오면 근거가 늘어난다 |
