목업에 도달하는 길

art-studio 와 2d-assets 를 읽고, 받은 배경을 실제 게임에 넣어 보고 정한 전략. 목표는 하나다 — 플레이 화면이 목업과 거의 같아지는 것.

한 장 요약

art-studio쓴다. 후보 → 디렉터 선택 → 승인 → export 라는 프로세스가 바로 필요한 것이다. 다만 실행 코드가 없어 손은 우리가 채운다
2d-assets떡락섬에는 쓰지 않는다. 화풍 · 시점 · 엔진 · 생산 방식 · 푸는 문제가 전부 다르다. 결함이 아니라 다른 게임을 위해 만들어진 것이다
가져올 것2d-assets 의 구조 — 카탈로그 · 후보 대조 시트 · 결정적 재현 · 검증 · export 분리. 코드가 아니라 설계다
가장 큰 발견배경을 지금 게임에 넣을 수 없다. 세로 그림과 가로 무대가 양립하지 않는다 — 아래에서 화면으로 확인했다

세 저장소의 자리

화면에서 확인한 것

받은 배경 1024×1536 을 실제 게임에 넣고 찍었다. 파일 하나 넣었을 뿐인데 코드 수정 없이 로드됐다 — 자리표시자 폴백은 설계대로 작동한다. 문제는 그다음이다.

세로 그림과 가로 무대는 양립하지 않는다. 배경을 쓰려면 월드 스테이지가 세로가 되어야 한다 — 기획서 §05 의 Modern UI Shell 이다.

그래서 순서가 정해진다. 셸이 배경보다 먼저다. 그림을 아무리 잘 뽑아도 들어갈 무대가 없다.

적용할 프로세스

원하는 것은 「생성 → 변주 → 선택지 제시 → 최종 선택」이다. art-studio 가 이미 그 구조를 갖고 있어 새로 만들 필요가 없다.

REFERENCE   목업 4장 · 게임 스크린샷
CONCEPT     방향 탐색 — 화풍이 정해졌으므로 대체로 건너뛴다
CANDIDATE   ★ 한 자산당 3~4장.  여기가 «변주»다
APPROVED    ★ 디렉터가 눈으로 고른 한 장.  여기가 «최종 선택»이다
EXPORT      게임 저장소 assets/ 로
RUNTIME     게임 화면에서 확인 → 아니면 CANDIDATE 로

지금 잘못돼 있는 것

게임 저장소에 후보가 쌓이고 있다. 후보 3~4장 × 자산 40개 = 160장이 게임 이력에 들어가면 저장소를 못 쓰게 된다. 지금 2장일 때 옮기는 게 싸다.

지금바뀔 곳
목업 (기준)게임 docs/mockups/스튜디오 references/
후보게임 docs/art/received/스튜디오 candidates/
승인본없음스튜디오 approved/
게임용없음게임 assets/

변주를 어떻게 가하는가

2d-assets 는 조합 폭발로 변주하지만 떡락섬에는 안 맞는다 — 명명된 인물이 8명이고 장면이 6개다. 한 장 한 장이 고유하다.

자산변주의 뜻장수무엇이 달라지는가
배경같은 장면의 다른 해석3~4시간대 · 카메라 높이 · 밀도 · 배치
초상화같은 인물의 표정표정당 2~3눈썹 · 시선 · 입. 얼굴 정체성은 고정
아이템 아이콘같은 물건의 형태2~3각도 · 낡음 정도
캐릭터여기가 어렵다 — 아래

캐릭터 — 진짜 어려운 문제

배경은 장당 1장이면 되지만 캐릭터는 다르다. 게임의 Actor.gd 가 요구하는 것을 실측했다.

걷기 방향당 6프레임 × 방향 4 = 24
대기 3 · 말하기 2
──────────────────────────
인물 하나당 약 29프레임 · 명명 인물 5명 → 145프레임

AI 이미지 생성기는 이걸 일관되게 못 만든다. 프레임마다 얼굴 · 옷 · 비율이 흔들린다. 목업에는 이 문제가 보이지 않는다 — 목업의 인물은 걷지 않기 때문이다.

방법장점대가
A컷아웃 퍼펫 — 파츠를 한 벌 만들고 엔진에서 변형프레임 일관성 문제가 사라진다Actor.gd 교체 · 파츠 경계
B프레임 생성 — 각 프레임을 AI로코드 변경 없음일관성이 최대 위험 · 145장 관리
C프레임 줄이기 — 걷기 2~3, 방향 2~3가장 싸다회화체에서 조악해 보일 수 있다
D미룬다 — 배경 · 초상화 먼저결정을 미룰 수 있고 인상은 크게 바뀐다캐릭터가 계속 도드라진다

권장: D 로 시작해 A 로 간다. 이유는 화면 면적이다 — 목업에서 캐릭터는 화면의 5~8%, 배경은 50~78%다. 배경과 초상화만 바꿔도 인상의 대부분이 바뀐다. 캐릭터 방식은 배경이 세로 셸에 얹힌 화면을 보고 정하는 편이 낫다.

단계와 판정

단계무엇을판정 — 무엇을 어떻게 확인하는가
0 · 자리 정리스튜디오 등록 · 후보 이관 · 대조 시트후보를 한 장에 모아 볼 수 있는가. 게임 git status 에 후보가 안 뜨는가
1 · 세로 셸탐색 화면 하나만이라도1024×1536 을 넣었을 때 왜곡 없이, 오브젝트가 다 보이고, 핫스폿이 제자리인가. 지금은 셋 다 실패한다
2 · 배경 6장장면당 3~4 후보 → 선택게임 화면에서 앵커와 나란히 놓고 같은 세계로 보이는가
3 · 초상화5명 × 표정 2~3같은 인물의 표정들이 한 사람으로 보이는가
4 · 캐릭터A/B/C/D 결정 후배경에 묻히지 않고, 걸을 때 어색하지 않은가
5 · 아이콘 · UI가장 나중가방 시트에서 작게도 구분되는가

초상화는 배경과 독립적이다. 세로 셸을 기다리지 않고 지금 진행할 수 있는 유일한 항목이다.

만들어 둔 것

전략만 적지 않고, 프로세스가 돌아가는 데 당장 없던 것 하나를 만들었다.

결정이 필요한 것

내가 정하지 않았다. 순서대로 답이 필요한 것들이다.

  1. 후보를 스튜디오로 옮길 것인가 — 지금 2장일 때가 가장 싸다
  2. 세로 셸을 먼저 할 것인가 — 화면 증거가 그렇게 말한다. 아니면 배경은 계속 못 들어간다
  3. 기준 캔버스 — 1080×1920 / 941×1672 / 그 외. 인물 · 아이콘 규격이 여기서 파생된다
  4. 캐릭터 제작 방식 — A/B/C/D. Phase 4 에서 정해도 된다
  5. 2d-assets 를 DICE DOMINION 전용으로 볼 것인가 — 여지를 남기면 화풍 오염 위험이 생긴다

확인하지 못한 것

  • Unity 설치 여부 — 떡락섬에는 무관하지만 재지 않았다
  • MCP 이미지 생성 연결 — 지금 세션에 생성 도구가 없다
  • 컷아웃 퍼펫이 이 화풍에서 자연스러운가 — 파츠 한 벌을 만들어 보기 전에는 모른다
  • 목업의 배틀 · 수첩 화면 월드 높이 — 자동 검출이 실패했다. 눈으로 재야 한다
  • 초상화 표정 수 — 대사 데이터에서 아직 뽑지 않았다
